# 微通道研究项目持久上下文

## 研究定位

本项目聚焦单相液冷嵌入式/歧管微通道，目标是面向芯片非均匀热点开展热-流体协同设计。分析结构时必须同时讨论换热、压降、流量分配、泵功、加工可行性及热源场景，不能仅凭仿生名称证明合理性。

## 当前形成的判断

1. PFMMC文献已经研究冷热侧非对称强化、热侧针翅位置、热歧管截面及微通道进出口宽度；继续做少量位置平移创新不足。
2. 推荐主线是从均匀热流下的均匀流量，转向非均匀热源下的“冷却流量与局部热负荷匹配”。
3. 高温工质停留时间可量化，但平均停留时间通常与V/Q重复。更有意义的是回流死区、RTD长尾、局部流龄及温度加权热暴露，并且只能作为辅助诊断，必须关联最高温度和泵功。
4. 算法入门路线：参数化Fluent模型 → LHS采样 → GPR/Kriging代理模型 → NSGA-II温度/泵功多目标优化 → Pareto候选点CFD回代 → 自适应加点。
5. 鱼鳍文献仅作为研究范本；不能默认鱼骨、叶脉或其他自然形态具有排液优势，必须建立自然功能、流体机理、结构变量和评价指标之间的闭环。

## 文献调用规则

新对话按固定顺序调用：先读取04和本02，再读取《00_微通道文献知识库_快速索引》，再按ID或标签检索《01_微通道文献知识卡片》；询问某篇论文的实验方法、微通道结构尺寸、加工方法、工作流体、流量/热流密度、测量仪器、边界条件、网格或不确定度时，必须继续按同一ID读取《03_微通道文献方法与结构参数证据库.jsonl》。如卡片的 `pdf_persisted=true`，可通过 `pdf_library_file_id` 或 `pdf_library_path` 定位原文。只有证据片段存在歧义，或涉及图表、公式、原句及正式引用时才打开原PDF；回答精确细节时应标明PDF页码与证据状态。卡片中的DOI为候选值，引用前必须核验。不能把两相沸腾机理直接套用于单相冷却。

## 分层保存与准确性规则

- `00`用于路由，不能用来回答具体尺寸。
- `01`用于判断论文内容和详细证据覆盖度；`key_parameter_mentions`只是快速候选，不能脱离参数定义使用。
- `03`保存页码关联的压缩证据片段，是详细问答的首选来源；页码均指PDF文件页码。
- 参数符号必须结合该论文的表格、图注或变量定义解释，不能仅凭相同字母跨论文推断。
- 若同一参数出现多个数值，应先判断其属于基准结构、参数扫描范围、优化结构或不同工况，禁止任意选择一个数值。
- `verbatim-extracted`表示从PDF文本层机械抽取，可能有双栏串行、断词或OCR错误；发现单位异常、语句拼接或物理上不合理时必须回看原PDF页面。
- 正式论文引用、公式、图片、表格和最终定量结论仍以原PDF为准。

## 后续导入默认动作

用户在本项目上传新的论文或压缩包时，默认执行以下流程：

1. 安全解包并拒绝路径穿越、可执行文件和异常嵌套内容；原压缩包只作为本轮输入，不替代逐篇PDF保存。
2. 对每个PDF计算SHA-256，并结合规范化题名、DOI和版本信息去重；同文不同版本只保留一个主记录，必要时在卡片中说明版本关系。
3. 使用PDF页树、页数、加密状态、正文可提取性和首末页文本进行完整性校验。损坏、空白、仅错误页或无法可靠解析的PDF不得上传到正式原文目录，也不得保留题名级占位；若旧索引已有该损坏记录，应从00、01、03同步删除。
4. 通过校验的每篇原PDF使用稳定文献ID命名为 `MC-xxx__题名.pdf`，保存到 `D:\data\微通道文献\原始PDF\`。不创建“新版”“最终版”等平行副本。
5. 在01卡片写入 `pdf_persisted`、`pdf_validation_status`、`pdf_sha256`、`pdf_pages`、`pdf_library_path`、`pdf_library_file_id` 与 `pdf_file_id`，建立索引到原PDF的双向定位信息。
6. 提取题名、作者、年份、DOI候选、相态、主题、研究方法和与当前研究主线的用途，增量更新00与01。
7. 从同一份已保存原PDF抽取带PDF页码的结构尺寸、工况、实验装置、数值方法、仪器与不确定度证据，增量更新03；若保存版本与旧证据来源的哈希不同，必须从保存版本重新抽取页码证据。
8. 最后进行一致性验收：00、01、03的有效ID集合相同；每个 `pdf_persisted=true` 的ID均能定位到原PDF；损坏ID不存在；重复文献只对应一个主ID；统计数量与文件目录一致。

预印本必须明确标注版本风险。除非用户另有说明，不把每篇论文全文重复改写成长摘要，而采用“快速索引—知识卡片—页码证据—原PDF”四层保存方式。
